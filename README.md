# 🤖 Matrix Family Bot

ربات تلگرام برای **مدیریت عضوگیری و پشتیبانی فمیلی (Family Matrix)**.
روی **Cloudflare Workers** اجرا می‌شود و دیتابیسش **Cloudflare D1** است. بدون سرور، بدون `npm install`.

---

## ✨ ربات چه کار می‌کند؟

### برای کاربر
| دکمه | کار |
| --- | --- |
| **درخواست عضویت** | یک فرم ۸ مرحله‌ای: اسم گیم، اسم واقعی، سن، فعالیت در دولت، اسکرین‌شات‌ها، معرف (اختیاری)، دلیل لیو/کیک از فمیلی قبلی، و یک ویس بالای ۵ ثانیه |
| **پشتیبانی / انتقادات** | کاربر پیام می‌نویسد و ادمین از داخل ربات جواب می‌دهد |

- کاربری که یک درخواست در حال بررسی دارد، نمی‌تواند درخواست دوم بدهد.
- جواب (تایید یا رد همراه با دلیل) از طریق همین ربات به کاربر می‌رسد.

### برای ادمین
- هر درخواست جدید با **عکس‌ها، ویس و فرم کامل** برای همه‌ی ادمین‌ها می‌آید و با دکمه‌ی **تایید** یا **رد** (با نوشتن دلیل) بررسی می‌شود.
- **پنل ادمین** شامل:
  - بن / آنبن کاربر
  - پیام همگانی (در دسته‌های ۲۰تایی، بدون تایم‌اوت)
  - فعال / غیرفعال کردن دریافت درخواست عضویت (با ذکر دلیل)
  - لیست درخواست‌ها و پیام‌های پشتیبانی بی‌پاسخ
  - تغییر اسم نمایشی ادمین
  - لیست ادمین‌ها همراه با آمار (تعداد تایید، رد و تیکت‌های جواب‌داده‌شده)
  - خالی کردن درخواست‌ها و پیام‌های در انتظار
- از لیست «درخواست‌های بی‌پاسخ» هر درخواست را که بزنید، **عکس‌ها، ویس و فرم کامل فقط برای همان ادمین** ارسال می‌شود.

### برای مالک (Owner)
- همه‌ی کارهای ادمین، به‌علاوه‌ی افزودن و حذف ادمین و **ریست کامل** دیتابیس (با دو مرحله تایید).

### گروه فمیلی (اختیاری)
- هر **درخواست عضویت جدید** و هر **پیام پشتیبانی جدید** علاوه بر ادمین‌ها، **یک بار** در گروه هم ارسال می‌شود.
- پیام‌های گروه دکمه ندارند؛ تایید، رد و جواب دادن فقط داخل ربات انجام می‌شود.
- دیدن بعدی یک درخواست از پنل ادمین، دوباره در گروه نمی‌آید.
- ربات داخل گروه به پیام‌ها جواب نمی‌دهد و اعضای گروه را به لیست کاربران اضافه نمی‌کند.

### لاگ
همه‌ی کارهای مهم (تایید، رد، بن، پیام همگانی، تغییر ادمین، ریست و...) در جدول `audit_logs` ثبت می‌شود و ادمین‌ها هم از کارهای هم باخبر می‌شوند.

## 🧱 دیتابیس (D1)

جدول‌ها در اولین درخواست **خودکار ساخته می‌شوند**؛ نیازی به اجرای SQL نیست.

`users` · `admins` · `settings` · `membership_requests` · `membership_request_images` · `membership_temp_photos` · `form_sessions` · `support_tickets` · `support_messages` · `audit_logs` · `broadcasts` · `broadcast_recipients`

## 🚀 راه‌اندازی (فقط با داشبورد کلادفلر، بدون ترمینال)

### ۱. ساخت Worker
Cloudflare Dashboard ← Workers & Pages ← Create ← Worker ← یک اسم بدهید ← Deploy.
بعد **Edit code** را بزنید، محتوای `worker.js` را جایگزین کد پیش‌فرض کنید و Save & Deploy.

### ۲. ساخت و اتصال دیتابیس D1
Workers & Pages ← D1 ← Create database (مثلاً `matrix-family-db`).
بعد در Worker: Settings ← Bindings ← Add ← D1 Database:
- Variable name: `DB`
- Database: همان دیتابیسی که ساختید

### ۳. ساخت Secretها
Worker ← Settings ← Variables and Secrets، سه Secret اضافه کنید:

| نام | مقدار |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | توکن ربات از @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | یک رشته‌ی تصادفی بلند به انتخاب خودتان |
| `OWNER_TELEGRAM_ID` | آیدی عددی تلگرام مالک |

> ⚠️ توکن و Secretها را هرگز داخل کد یا گیت‌هاب نگذارید.
> آیدی عددی خودتان را با ارسال `/whoami` به ربات هم می‌توانید ببینید.

### ۴. فعال‌سازی وب‌هوک
این آدرس را در مرورگر باز کنید:

```
https://<آدرس-worker-شما>.workers.dev/setup?token=<TELEGRAM_WEBHOOK_SECRET>
```

اگر جواب JSON با `"ok": true` دیدید، ربات فعال است.

### ۵. (اختیاری) اتصال گروه فمیلی
1. ربات را عضو گروه کنید (ادمین بودنش لازم نیست).
2. **مالک** داخل گروه بفرستد: `/setgroup` ← ربات تایید می‌کند.
3. برای قطع کردن: `/unsetgroup`.

اگر گروه بعداً به سوپرگروه ارتقا پیدا کرد، آیدی آن عوض می‌شود؛ دوباره `/setgroup` بفرستید.

## 💬 دستورها

| دستور | کجا | کار |
| --- | --- | --- |
| `/start` | چت خصوصی | شروع و نمایش منو |
| `/whoami` | چت خصوصی | نمایش آیدی شما و بررسی اینکه مالک شناخته می‌شوید یا نه |
| `/setgroup` | داخل گروه، فقط مالک | ثبت گروه برای دریافت اعلان‌ها |
| `/unsetgroup` | داخل گروه، فقط مالک | حذف گروه |

## 📝 نکات فنی
- فقط یک بایندینگ لازم است: `DB` (D1). از R2، KV، Queue یا Durable Object استفاده نمی‌شود.
- وب‌هوک با هدر `x-telegram-bot-api-secret-token` تایید می‌شود و درخواست‌های بدون آن رد می‌شوند.
- پیام همگانی در دسته‌های کوچک و در طول درخواست‌های وب‌هوک بعدی ادامه پیدا می‌کند، پس لیست بزرگ باعث تایم‌اوت نمی‌شود.
- کاربر بن‌شده هیچ جوابی از ربات نمی‌گیرد.
